ACCESS SYSTEM

How the key system works

Understand temporary sessions, checkpoint confirmation, expiration, and safe handling of generated keys without treating a verification screen as permanent content.

Alter Hub documentationUpdated August 20, 2026

What a key session is

A free key session is temporary. The server creates a session for the current device, tracks checkpoint progress, and generates a final key only after the required verification flow is completed.

The current Worker code uses expiring session records rather than treating every key link as permanent. That is why a copied key-session URL can stop working later even when the main website is still online.

How checkpoints work

The key interface presents three verification stages. At each stage you choose one of the currently offered providers. Progress is advanced after the selected provider confirms completion and the user returns to Alter Hub.

Do not open several competing checkpoint sessions for the same step. The current flow can replace a previous provider choice when a new provider is selected, which is intended to prevent one session from being completed more than once.

Why sessions and keys expire

Temporary sessions reduce the value of old shared links and make it possible to reject stale verification attempts. A completed key can also have its own validity period. If the page explicitly says the session or key has expired, generate a new access session instead of repeatedly refreshing the old result URL.

  • Session expired: start a new key session from the official access path.
  • Invalid link: confirm that the URL was copied completely and that it came from the current flow.
  • Checkpoint already used: return to the current session rather than retrying the same callback.
  • Key expired: obtain a fresh key through the current access method.

Keep the key private

A generated key should be treated like a temporary credential. Do not post it in Discord, screenshots, videos, or issue reports. Support generally needs the error message and the step that failed, not the full key itself.

For more information about device and session data, read the Privacy Policy.
