How these guides are written

Alter Hub's public documentation should describe behavior that can actually be checked. We avoid inventing feature lists, compatibility promises, or release histories just to make a page longer. When a game update changes behavior, the guide should be updated or the limitation should be documented.

Useful content comes first. Access, checkout, key, and verification pages are functional screens. They are not treated as documentation and are not where advertising should be placed.

If you find a guide that is out of date, include the page name, the step that differs, and a screenshot when you contact support. That makes the documentation itself easier to keep accurate.
